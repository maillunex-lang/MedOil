# Industrial Empire: правила ИИ-исполнителей

## Полностью автоматический цикл
1. Прочитай README.md, docs/decisions/APPROVED.md и GDD задачи.
2. Выполни `python tools/work_plan.py next`; бери первую доступную задачу, у которой нет активного PR. Проверь существующие PR прежде чем начинать дубликат.
3. Создай ветку `task/<ID>-<slug>`, реализуй, добавь релевантные тесты, запушь и открой PR с заголовком `[ID] Название задачи`, например `[S0-01] Каркас монорепозитория`.
4. GitHub Actions автоматически проверяет дорожную карту и сливает обычный PR после успешных обязательных проверок. Не жди ручного подтверждения. Если слияние блокируется GitHub или конфликтом, сообщи причину, не обходи ограничения.
5. После слияния workflow автоматически ставит `done` и обновляет ROADMAP.md. Не ставь done в рабочей ветке.
6. Следующий ИИ снова выполняет `next` и продолжает работу.

## Правила
- Основной источник задач: tasks/tasks.json. ROADMAP.md генерируется автоматически.
- Никакой прямой записи в main исполнителями. Только PR и автоматический workflow.
- Не изменять чужие зоны, контракты и утверждённые решения без отдельной задачи.
- Все деньги, количества и сроки обрабатываются детерминированно, без float для денег.
- Секреты, ключи подписи, production-пароли не хранить в GitHub.
- VPS и публикацию APK не трогать без отдельного разрешения.
- Задача считается завершённой только после merge и автоматического коммита статуса.
- Если workflow не смог обновить статус, следующий исполнитель сначала восстанавливает статус из подтверждённого PR, а не повторяет уже слитую задачу.
