# MONOREPO-01. Каркас монорепозитория

Согласовано с TECH-01 и GDD 11. Источник правды о составе модулей: `contracts/monorepo/manifest.json`.

## Верхнеуровневые модули

| Путь | Назначение | Поток задач |
|------|------------|-------------|
| `server/` | Go modular monolith, transport → application → domain → repository | A |
| `economy/` | Эталонные модели и golden-тесты (деньги, склады, производство) | B |
| `client/` | Godot 4.x Android, landscape, 3D isometric | C |
| `assets/` | Ресурсы с `asset_id`, footprint, LOD | D |
| `contracts/` | JSON Schema, общие типы, манифест монорепозитория | S0 |
| `tools/` | Планировщик задач, вспомогательные CLI | S0 |
| `docs/` | GDD, архитектура, QA | S0 |

Уже существующие каталоги вне модулей: `tasks/` (реестр `tasks.json`), `.github/` (CI).

## Инварианты (не нарушать в любых модулях)

- Деньги — только целые копейки; массы, объёмы, энергия — целые минимальные единицы (D-104).
- Сервер авторитетен для денег, складов, времени, собственности, логистики, контрактов.
- Секреты и production-пароли не коммитить; APK и VPS — только по отдельному разрешению.

## Проверка каркаса

```bash
python3 -m unittest discover -s contracts/monorepo -p 'test_*.py' -v
python3 contracts/monorepo/validate.py
```

В PR обязательный workflow `Monorepo scaffold` сверяет манифест с файловой системой.

## Зоны ответственности исполнителей

Каждая задача в `tasks/tasks.json` поле `scope` ограничивает изменяемые пути. Новые зависимости между модулями (импорты Go, ссылки клиента на контракты) фиксируются в контрактах до реализации в `server/` или `client/`.
